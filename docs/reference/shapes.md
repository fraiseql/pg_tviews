# Supported shapes

Which definitions pg_tviews maintains, how, and which it refuses. Each row names the
tests that prove it: regression tests under `test/sql/regress/`, and the TVIEW of the
same shape in the differential suite (`test/sql/differential/schema.sql`), whose random
writes check after every statement that each TVIEW equals its view
([its README](../../test/sql/differential/README.md)).

## How a shape is maintained

- **Row by row**: a write refreshes the TVIEW rows it reaches, at the end of the
  statement. The key is read off the changed row (`local`), found by a query over the
  statement's changed rows (`mapped`), or reached through an embedded TVIEW's refresh
  (`propagated`); `tviews.registry.cascade_kinds` shows which, per table
  ([How a write finds the TVIEW rows to
  refresh](ddl.md#how-a-write-finds-the-tview-rows-to-refresh)).
- **Through the policy**: a table nothing links to the key is `all_keys`, and the
  TVIEW's `uncascaded_policy` (or `uncascaded_tables` for that table) decides, at create
  time: `error`, the default, refuses the definition (`22023`, the hint says what to
  declare); `full_refresh` refreshes the whole TVIEW at the flush of a write to that
  table; `warn` leaves the rows stale until something else refreshes them ([Tables no
  cascade reaches](ddl.md#tables-no-cascade-reaches)). The definition's other tables
  stay row by row.
- **Refused**: nothing is created, with the SQLSTATE given.

## Shapes

The rows are grouped by the six axes of the dialect: what a definition states and
outputs, which relations it reads, how it reads a column, what its values depend on
besides the rows, time, and the staleness it declares. A definition is maintained when
each of its constructs is. The tables are generated from
[`dialect.toml`](dialect.toml), which also names the source deciding each row.

### A. Statement and output

| Shape | Example | Maintained | Evidence |

| Joins (inner, outer, chains, non-equality conditions) | `FROM tb_line l JOIN tb_order o ON o.pk_order = l.fk_order JOIN tb_customer c …` | row by row (`mapped`): one mapping query per statement; a row moved to another parent refreshes both | `lineage/regress_key_mapping_queries.sql`; `lineage/regress_outer_join_links.sql`; `cascade/regress_parent_change.sql`; differential `tv_purchase`, `tv_line` |
| Copied parent columns | `'author', jsonb_build_object('name', u.name)` over a join on `fk_user` | row by row: the changed value is written into every row holding the parent's key, in one statement; a parent read with a condition of its own (`AND o.deleted_at IS NULL`), or whose key changes, recomputes the rows instead | `cascade/regress_fanout_patch.sql`; `cascade/regress_nested_fanout.sql`; `cascade/regress_fanout_patch_soundness.sql` |
| Aggregate (`GROUP BY`) | `SELECT o.fk_user AS pk_user_summary, … GROUP BY o.fk_user, …` | group by group: each touched group is recomputed. | `DISTINCT ON` | `SELECT DISTINCT ON (c.id_contract) c.id_contract AS pk_contract, … ORDER BY c.id_contract, c.version_no DESC, c.pk_contract` | row by row, keyed on the `DISTINCT ON` key ([ADR 0169](../adr/0169-tview-row-identity.md)); a row changing its key refreshes the old and the new group. | Correlated subqueries, `LATERAL` | `(SELECT jsonb_agg(… ORDER BY c.pk_comment) FROM tb_comment c WHERE c.fk_post = p.pk_post)` | row by row when a condition links the subquery to the key | `lineage/regress_key_mapping_queries.sql`; `lineage/regress_statement_mapping.sql`; `arrays/regress_array_path_joins.sql`; differential `tv_nlat` |
| Uncorrelated subquery | `(SELECT count(*) FROM tb_flag)` | through the policy | `policy/regress_uncascaded_policy_default.sql`; `policy/regress_uncascaded_policy_option.sql` |
| Arrays of keys | `a.pk_node = ANY (<array>)`, `unnest(<array>)`, `LATERAL unnest(…)` | row by row, mapped through `<array> @> ARRAY[<key>]` | `arrays/regress_array_path_joins.sql`; `arrays/regress_unnest_cast.sql`; differential `tv_nsrf`, `tv_nlat`, `tv_nany`, `tv_ncast` |
| Join on a computed column | `x.code = s.upper_name`, `upper(n.name) AS upper_name` in a subquery | row by row when the expression is immutable; a stable one goes through the policy | differential `tv_nbadge` |

| TVIEWs reading each other in a cycle | `tv_a` reads `tv_b`, which reads `tv_a` | refused (`42P17`) | `operations/regress_error_codes.sql` |

| Not exactly one `SELECT` | two statements, a `DO` block | refused (`42601`) | `operations/regress_error_codes.sql` |

### B. Relations read

| Shape | Example | Maintained | Evidence |
|---|---|---|---|
| Embedded TVIEW (cascade) | `JOIN tv_user u ON u.pk_user = p.fk_user`, `'author', u.data` | row by row (`propagated`): a refresh of `tv_user` refreshes the posts embedding it, in the same flush | `cascade/regress_refresh_cascades_to_dependents.sql`; `cascade/regress_embeds_by_oid.sql`; differential `tv_deal`, `tv_desk`, `tv_note` |
| Another TVIEW's table read otherwise (an aggregating view over `tv_line`) | `LEFT JOIN v_line_totals t ON t.fk_order = o.pk_order` | row by row (`mapped`), like a base table; a read nothing links goes through the policy | `lineage/regress_tview_table_reads.sql`; differential `tv_ordsum` |
| Materialized view | `LEFT JOIN mv_line_count m ON m.fk_order = o.pk_order` | through the policy; under `full_refresh`, `REFRESH MATERIALIZED VIEW` refreshes the whole TVIEW in the same transaction | `policy/regress_materialized_view.sql`; differential `tv_ordcount` |
| Foreign table, sequence | `JOIN tb_remote r …`, `SELECT last_value FROM s_counter` | through the policy, except that `full_refresh` is refused (`22023`): nothing tells pg_tviews when they change. Declare `warn` and call `pg_tviews_refresh()` | `ddl/regress_untrackable_sources.sql` |
| Table read with its inheritance children (no `ONLY`) | `FROM tb_animal` with a child table | refused; `FROM ONLY` is row by row, and the table gets no new child (`0A000`) | `ddl/regress_untrackable_sources.sql` |
| Partitioned base table | `tb_event` partitioned by range | row by row through a row trigger on the root; every partition gets the flush and `TRUNCATE` triggers, so writes naming a partition refresh too. `DROP`, `DETACH` and `ATTACH` of a partition refresh the rows it carries | `refresh/regress_partition_direct_write.sql`; `refresh/regress_partitioned_entity_table.sql`; `ddl/regress_partition_truncate_attach.sql`; `ddl/regress_issue_261_partition_drop.sql` |
| Table a logical replication subscription writes | a TVIEW over a subscribed table | refused: the apply worker fires no statement trigger. Create the TVIEW on the publisher and publish its table (`0A000`) | `test/replication/logical_subscriber.sh` |
| Temporary table | `FROM pg_temp.tb_scratch` | refused by PostgreSQL (`cannot create temporary relation in non-temporary schema`) | not covered by a regression test |
| Row security that applies to the TVIEW's owner on a table it reads | a table the owner does not own with row security enabled, or one it owns that is forced | refused, at create, at re-derivation, and at the write that finds it set since: a refresh must read every row. ### C. How a column is read

| Shape | Example | Maintained | Evidence |
|---|---|---|---|
| Generated columns | `code text GENERATED ALWAYS AS (upper(name))` | `STORED`: an ordinary column. Virtual (PostgreSQL 18's default): followed through its inputs, also as a key or join column | `lineage/regress_virtual_generated_columns.sql`; differential `tv_vnote` |
| A table's whole row | `to_jsonb(t)`, `jsonb_agg(c ORDER BY c.pk_c)`, `t::text`, `f(t)` | row by row, every column of the table read: any UPDATE of it refreshes, none is patched in place. A view's whole row reads the view's columns | `lineage/regress_wholerow_root.sql`; `lineage/regress_wholerow_child_collection.sql`; `lineage/regress_wholerow_function_argument.sql`; `lineage/regress_wholerow_text_cast.sql` |
| System columns `xmin`, `tableoid` | `v.xmin::text AS version`, the partition a row is in | row by row: every UPDATE of the table refreshes (each changes `xmin`); `tableoid` follows a row moved to another partition | `lineage/regress_system_column_read.sql`; `freshness/regress_tableoid_cross_partition.sql` |

### D. What a value depends on besides rows

| Shape | Example | Maintained | Evidence |
|---|---|---|---|
| Function that reads tables (not `IMMUTABLE`, outside `pg_catalog`) | `name \|\| label_suffix()` | the tables declared in `function_reads` go through the policy. Undeclared, refused (`22023`) under `error` and `full_refresh` | `policy/regress_function_reads.sql`; `freshness/regress_aggregate_function_reads.sql`; `freshness/regress_operator_function_reads.sql`; differential `tv_custbadge` |
| Volatile function, wherever it is called | `random()`, `gen_random_uuid()`, `nextval()`, a `VOLATILE` function of yours, an operator or cast it backs | refused: two evaluations over the same rows may differ, and pg_tviews stores one. Compute the value when the row is written and store it in a column (`0A000`) | `lineage/regress_dialect_refusals.sql` |
| Built-in that reads the session, the transaction, the server, privileges or statistics | `SESSION_USER`, `pg_backend_pid()`, `inet_client_addr()`, `txid_current()`, `has_table_privilege(…)`, `pg_stat_get_live_tuples(…)` | refused: its value changes with no write, and no refresh follows it. Built-ins that read only their arguments and the settings the owner frame pins (`to_char`, casts, `current_database()`) are accepted (`0A000`) | `lineage/regress_dialect_refusals.sql` |
| Who reads the TVIEW | `CURRENT_USER`, `CURRENT_ROLE`, `USER`, `current_user()` | refused: a TVIEW's rows are the same for every reader, refreshed as its owner. Filter readers with a policy on `tv_*` (`0A000`) | `freshness/regress_reader_functions_refused.sql` |
| Row order reaching the output: `jsonb_agg`, `array_agg`, `string_agg`… (any user aggregate, `sum`/`avg` of a float), `LIMIT`/`OFFSET`, `ARRAY(SELECT …)`, `DISTINCT ON`, `row_number()`, `first_value()`… | `jsonb_agg(c.label ORDER BY c.pos, c.pk_c)` | accepted when its `ORDER BY`, with the level's equalities and the tables' unique keys, determines every row (or every value the aggregate reads); when at most one row reaches it; when an aggregate is ordered by the values it aggregates and they render as they compare (not `numeric`, floats, `jsonb`); when a `UNION ALL` is ordered by a constant rank. Otherwise refused, the hint naming a key to append (`0A000`) | `lineage/regress_order_rule.sql`; `freshness/regress_unordered_aggregate.sql` |

## Writes the rows above do not cover

- An `UPDATE` that changes no column the TVIEW reads refreshes nothing; one that
  changes only columns copied into `data` as they are patches the documents in place
  instead of recomputing them (`direct_patch/` tests).
- `TRUNCATE` of a base table refreshes the whole TVIEW
  (`lineage/regress_statement_mapping.sql`,
  `transactions/regress_truncate_in_writing_statement.sql`).
- `COPY FROM` refreshes like an `INSERT` (`transactions/regress_copy_from.sql`).
- A trigger of yours that writes base tables, on a base table or on a `tv_*` table:
  [Firing order](ddl.md#firing-order).
